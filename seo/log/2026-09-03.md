### The reporting hole this exposed

`report_gsc.py` was written last run precisely so that no signal would sit unread
in a file again. It did not print `ai10325` anywhere, in either of the two files
in `seo/gsc/`.

The cause is structural rather than a bug in any one table. The striking distance
table starts at position 5. The "nothing of ours ranks" table starts at position
20. The split table needs more than one of our pages on the query. A query the
site ranks 1 to 4 for, on one page, falls through all three. That band is where
the single largest row on the site lives, and in both files it was invisible.

## Changed

1. **`scripts/report_gsc.py` prints the band above position 5 first.** One table,
   the same shape as the others, with an extra column giving each row's share of
   total impressions, which is the number that makes a row like this legible. On
   `2026-09-01.json` it prints one row, `ai10325`, 121 impressions, 17%. On
   `2026-08-30.json` it prints the same row at 94 impressions and 12%, which is
   what was sitting unread. Committed to `main`.
2. **`ROUTINE.md` Step 2 gained that band as its first bullet**, with the
   instruction that follows from the finding: before reading a large row here as
   demand, search the query itself and see what else it means. Committed to
   `main`.

Both are maintenance and went to `main`. No pull request was opened, because no
published prose changed.
