`git status` now lists `docs/blog/index.html` and
`docs/blog/stripe-decline-codes-that-stop-retries/index.html` as modified. **They are not.**
Both files are byte-identical to `HEAD`, and `git hash-object` on each returns the same blob
the index and `HEAD` both hold. `git diff --raw -- docs` is empty and exits 0. What the
working tree actually has is a line-ending stat artifact: git warns that LF will be replaced
by CRLF the next time it touches these two files, and `git update-index --refresh` does not
clear the flag.

that someone hand-edited a generated page, is wrong and would cost a run to disprove. Check
the blob hashes, not the status flag. Nothing was staged, reverted or normalised here; a
