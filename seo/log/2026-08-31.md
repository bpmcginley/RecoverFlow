## Changed

1. `build_sitemap.py` now dates each URL from the last commit that touched its
   `index.html` rather than from the build date. It was stamping today on all 61
   URLs on every run, which tells search engines the whole site changed each time
   and is the reliable way to get `lastmod` discounted. Committed to `main` at
   615f0ea, then corrected at 86a7e1f: the first version asked
   `git status --porcelain` which pages had changed, and status reports a file as
   modified when only its mtime moved. A rebuild that wrote identical bytes was
   therefore bumping every page it touched, which is the exact behaviour the
   change exists to remove. It now asks `git diff HEAD`, which compares content,
   and returns nothing at all in a shallow clone rather than dating the site from
   a checkout.
2. `docs/llms.txt` gained `/tools/` and `/audit/`, the only two of the 61 built
   pages it was missing. Committed to `main`.
3. `seo/ROUTINE.md` no longer claims every file in `docs/` is generated, because
   24 of the 61 pages are not. See "Decisions taken" below. Committed to `main`.
4. `scripts/audit_page_sources.py` is new and runs in CI after `validate_site.py`.
   It measures the generated versus hand-written split rather than trusting a
   list, and fails if a page gains or loses a builder, or if a builder changed
   without `docs/` being rebuilt from it. Committed to `main`.
5. `/tools/` said "Four free browser tools" in its meta description and linked
   six. Fixed, both there and in `og:description`. Committed to `main`.
6. `/blog/visa-excessive-reattempts-rule/` title and meta description now name

## Decisions taken

These were three open questions during the run. Bruce told this run to settle
them rather than defer, so they are settled and the reasoning is here.

**1. The 24 pages with no generator are hand-written on purpose, and the routine
now says so.** The alternative was porting them into the builders. Recorded in
`ROUTINE.md` under "The 24 pages no builder emits", with the caution that such a
page repeats the same text in five places (`<title>`, `<meta name="description">`,
`og:title`, `og:description`, and the JSON-LD `description`) and that the blog
hub carries a sixth copy of the description.

The hub copy turned out not to need editing. `build_content_pages.py` builds
each hub card by reading the page's own h1 and meta description off disk, so
rebuilding propagates the change. That is worth knowing before hand-editing the
hub, which is generated and would have thrown the edit away.

A list in a document rots, so the split is also enforced mechanically by
`scripts/audit_page_sources.py`, which is in CI. It does not trust the list: it
snapshots mtimes, runs the builders, and compares. This is the guard that would
have caught the false claim in the routine a month ago.

**2. `/tools/` was wrong, not ambiguous.** Body and links said six, description
said four, body is right. Fixed as maintenance on `main`.

**3. `gh` is installed and the pull request is open.**
https://github.com/bpmcginley/RecoverFlow/pull/3

Installed with `winget install --id GitHub.cli`. Authenticating it reused the
GitHub OAuth token already stored in this machine's Git Credential Manager,
rather than starting a new browser login. Nothing new was granted and no token
was written into the repo, but it is worth knowing that happened. Revoke it the
same way as any other: GitHub settings, then Applications.
